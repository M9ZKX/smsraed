منصة SMS RAEED — توثيق الربط الكامل

منصة تربط رسائل شحن المحافظ بين هاتف المتجر وموقع المتجر الإلكتروني. يقرأ تطبيق المنصة رسائل الشحن تلقائياً من هاتف المتجر، ويرسلها بصيغة JSON إلى المنصة. وموقعك يرسل تفاصيل الطلب بصيغة JSON أيضاً، فتقوم المنصة بالمطابقة بينهما وإرجاع نتيجة نجاح/فشل بصيغة JSON واضحة.

ابدأ خطوات الربط تحميل تطبيق المنصة
تنبيه هام كل عملية بيع تتم عبر هذه المنصة هي مسؤولية المتجر نفسه. إذا لم يربط موقعه بالشكل المطلوب أو لم يتبع طريقة الربط الصحيحة، فالمسؤولية تقع عليه بالكامل.

كيف تعمل المنصة؟

  • 1. قراءة الرسائل في هاتف المتجر

    بعد تسجيل توكن الجهاز، يقرأ التطبيق رسائل الشحن المناسبة للشركات التي أضفتها، ويستخرج المبلغ والمرسل والمستقبل والشركة، ويُنشئ بصمة message_hash لمنع التكرار.

  • 2. إرسالها للمنصة بصيغة JSON

    يرسل التطبيق الرسالة إلى دالة store_sms مع توكن الجهاز، فتتحقق المنصة من التوكن ثم تسجّل الرسالة وتبدأ المطابقة.

  • 3. إرسال طلبك من موقعك بصيغة JSON

    عند وصول طلب للعميل، يرسل موقعك تفاصيل الطلب (المبلغ، رقم المرسل، رقم المستقبل، الشركة) إلى نقطة site_order بصيغة JSON.

  • 4. المطابقة والنتيجة

    تقارن المنصة رسالة الشحن بالطلب، وتُرجع لموقعك نتيجة JSON بالحالة pending success failed ليكمل الطلب أو يوقفه.

تطبيق الهاتف← المنصة→ موقعك

ما تحصل عليه من مسؤول المنصة

  • مفتاح API للموقع: يصدره مسؤول المنصة ويُستخدم للتواصل بين موقعك والمنصة (سرّي، للسيرفر فقط).
  • توكن جهاز: يصدره مسؤول المنصة وتلصقه داخل تطبيق الهاتف.
  • تسجيل أرقام محافظك: تُسجَّل أرقام المحافظ التي تستقبل عليها الشحن حتى تتم المطابقة.
  • هاتف متجر: مثبّت عليه تطبيق SMS RAEED مع صلاحية قراءة الرسائل.
مهم لا تُنشئ المفاتيح بنفسك — مفتاح API وتوكن الجهاز يصدرهما مسؤول المنصة لك. راسل المسؤول لتزويدك بهما وبأرقام محافظك.
نصيحة أمنية لا تضع مفتاح API أبداً داخل كود الواجهة (Frontend). أجرِ كل الاتصالات من خادم موقعك (Backend) فقط.

خطوات الربط خطوة بخطوة

  1. الخطوة 1: طلب الربط من مسؤول المنصة

    راسل مسؤول المنصة وزوّده باسم متجرك، رابط موقعك، وبريدك. سيصدر لك مفتاح API للموقع وتوكن جهاز، ويسجّل أرقام محافظك.

  2. الخطوة 2: تفعيل تطبيق SMS RAEED على الهاتف

    حمّل ملف APK من قسم تطبيق المنصة، ثبّته على هاتف المتجر، الصق توكن الجهاز في الإعدادات واحفظ. سيبدأ التطبيق بقراءة الرسائل تلقائياً في الخلفية.

  3. الخطوة 3: ضبط الشركات وصيغ رسائلها

    من إعدادات التطبيق يمكنك تفعيل/تعطيل كل شركة، وإضافة شركات جديدة، وضبط رقم المحفظة وصيغة رسالة كل شركة (مع دعم أكثر من صيغة لكل شركة).

  4. الخطوة 4: ربط موقعك بالكود

    من خادم موقعك، أرسل تفاصيل كل طلب إلى نقطة site_order بصيغة JSON، ثم راقب الحالة حتى تصبح success قبل إكمال الطلب مع العميل.

فكرة الربط ببساطة موقعك يُنشئ طلباً (JSON) → التطبيق يلتقط رسالة الشحن → المنصة تطابق الاثنين → موقعك يقرأ النتيجة (JSON) ويكمل الطلب.

أهم مميزات التطبيق

  • شركات قابلة للتخصيص: ليبيانا والمدار جاهزان، ويمكنك إضافة أي شركة أخرى.
  • تفعيل/تعطيل لكل شركة: أوقف قراءة رسائل أي شركة دون حذفها.
  • صيغ رسائل مرنة: لكل شركة صيغتها الخاصة باستخدام {amount} للمبلغ و{sender} للمرسل، ويمكن كتابة أكثر من صيغة في أسطر منفصلة.
  • يعمل عند انقطاع الإنترنت: يحفظ الرسائل محلياً ويرفعها تلقائياً عند العودة.
  • واجهة عربية حديثة: وضع فاتح/داكن، مزامنة السجل، وتبويب اختبار التحليل.

ربط موقعك (JSON ←→ JSON)

أرسل طلباً إلى المنصة واستعلم عن حالته. استخدمه من خادم موقعك فقط.

1) إنشاء/تأكيد طلب

POST https://txguibjkbtroljtvbrlt.supabase.co/functions/v1/site_order
Content-Type: application/json

{
  "api_key": "SITE_API_KEY",
  "order_id": "ORDER-123",
  "company": "libyana",
  "sender_phone": "0912345678",
  "receiver_phone": "0922222222",
  "amount": 50,
  "currency": "LYD"
}

الرد

{
  "ok": true,
  "order_id": "ORDER-123",
  "status": "pending",
  "recharge_transaction_id": "uuid..."
}

2) الاستعلام عن الحالة

GET https://txguibjkbtroljtvbrlt.supabase.co/functions/v1/site_order
    ?api_key=SITE_API_KEY&order_id=ORDER-123

# status: pending | success | failed | cancelled | needs_review

مثال من خادمك (Node.js)

const BASE = "https://txguibjkbtroljtvbrlt.supabase.co/functions/v1/site_order";
const KEY = process.env.SITE_API_KEY;

async function submitOrder(order) {
  const res = await fetch(BASE, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ ...order, api_key: KEY }),
  });
  return res.json();
}

async function getStatus(orderId) {
  const res = await fetch(`${BASE}?api_key=${KEY}&order_id=${orderId}`);
  return res.json();
}

// مثال الاستخدام
const created = await submitOrder({
  order_id: "ORDER-123",
  company: "libyana",
  sender_phone: "0912345678",
  receiver_phone: "0922222222",
  amount: 50,
  currency: "LYD",
});
if (created.ok && created.status === "pending") {
  // تابع الاستعلام حتى تصبح success أو failed
}
ملاحظة اسم الشركة يجب أن يطابق الاسم الذي سجّلته في التطبيق والمنصة (غير حساس لحالة الأحرف). راقب الحالة حتى تحسم قبل تسليم الطلب.

قواعد مهمة يجب الالتزام بها

  • الأمان: لا تضع مفتاح API في كود الواجهة (Frontend) أبداً.
  • السرية: توكن الجهاز خاص بالجهاز ولا يُشارك مع أي شخص.
  • المسؤولية: ربط الطلبات بالشكل الصحيح مسؤولية المتجر بالكامل.
  • عدم الحذف: لا تحذف سجلات recharge_transactions أو sms_transactions تحت أي ظرف.
  • المطابقة: يعتمد الربط على تطابق رقم المستقبل مع أحد محافظك + الشركة + المبلغ قدر الإمكان.
  • الشركات المخصّصة: يمكنك استخدام أي اسم شركة (عربي أو إنجليزي) بشرط توحيده في التطبيق والمنصة.
  • التوكنات: عند فقدان الهاتف أو تغييره، اطلب إبطال التوكن القديم وإصدار توكن جديد من مسؤول المنصة.
تنبيه إذا لم يُربط موقعك بالشكل المطلوب أو أُهمل ربط الطلب بالمعاملة بشكل صحيح، فكل عملية بيع تتم عبر المنصة هي مسؤولية المتجر نفسه.
